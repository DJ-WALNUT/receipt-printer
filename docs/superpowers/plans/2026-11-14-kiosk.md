# 영수증 프린터 키오스크 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 콘텐츠 폴더마다 둔 `content.toml` 하나로 터미널 메뉴와 아이패드 키오스크 화면이 함께 만들어지게 하고, 라즈베리파이에서 키오스크 서버가 자동으로 뜨게 한다.

**Architecture:** `hub.py`가 설정 파일을 읽고, 입력값을 검사해 스크립트 인자 목록으로 바꾼다. 터미널(`main.py`)과 웹 서버(`kiosk/`)는 둘 다 `hub.py`만 거쳐 콘텐츠를 안다. 웹 서버는 인쇄 작업을 대기열 하나에 넣어 한 번에 하나씩, 지금처럼 장마다 새 프로세스로 스크립트를 실행한다.

**Tech Stack:** Python 3.13+(표준 `tomllib`), Flask, waitress, pytest, 빌드 없는 HTML/CSS/JS, systemd.

**Spec:** `docs/superpowers/specs/2026-11-14-kiosk-design.md`

## Global Constraints

- 콘텐츠 스크립트는 Task 0(시드번호 글자)에서만 고친다. 그 밖에 고치는 기존 파일은 `main.py`, `receipt.py`(대체 글꼴 목록만), `README.md`, `docs/작업-정리.md`, `.gitignore`뿐이다.
- **브랜치 배치**: Task 0~3과 Task 7의 `receipt.py` 대체 글꼴은 `receipt-contents`에 커밋한다. Task 4~7의 나머지는 그 뒤 `receipt-contents`에서 만든 `kiosk` 브랜치에 커밋한다.
- **`kiosk` 브랜치는 `kiosk/`, `deploy/`, `tests/kiosk/` 안의 파일만 추가한다.** `receipt-contents`에 있는 파일(`README.md`, `requirements.txt`, `.gitignore` 포함)은 `kiosk`에서 고치지 않는다. 그래야 `git merge receipt-contents`가 충돌 없이 끝난다. 키오스크 설명서는 `kiosk/README.md`, 키오스크 패키지는 `kiosk/requirements.txt`(`-r ../requirements.txt`, `flask`, `waitress`), 닉네임은 `kiosk/nicknames.txt`, 키오스크 테스트는 `tests/kiosk/`에 둔다.
- 영수증과 화면에 찍히는 번호의 이름은 "시드번호"다.
- `python main.py <이름> <옵션…>`과 각 스크립트 직접 실행은 지금과 똑같이 동작해야 한다.
- 방문자는 한 번에 최대 4장, 운영자(터미널, 관리자 화면)는 최대 20장.
- 방문자 제한은 화면에서 숨기는 것이 아니라 `hub.py`에서 거부한다.
- 스크립트는 셸 없이 인자 목록으로 실행한다 (`subprocess.run([sys.executable, script, *args])`).
- `text`는 키오스크에 올리지 않는다.
- PC(Windows, Python 3.14)와 파이(Python 3.13) 양쪽에서 돌아야 한다. 경로는 `pathlib`, 파일은 `encoding="utf-8"`로 연다.
- 사용자에게 보이는 글은 모두 한국어다.
- 테스트는 `.venv\Scripts\python -m pytest`로 돌린다.
- 아래 작업 본문이 이 절이나 Task 0과 어긋나면 이 절과 Task 0이 우선한다 (본문은 브랜치를 나누기 전에 쓴 것이다). 특히: `requirements.txt`에 `flask`, `waitress`를 넣지 않는다. 닉네임 파일과 방문자 닉네임 테스트는 Task 5로 옮긴다. Task 7의 README 내용은 `kiosk/README.md`에 쓴다. 시드번호 예시와 정규식은 Task 0의 표를 따른다.

## Review Focus

1. **새 콘텐츠의 설정 파일에 오타가 있다** → 그 콘텐츠만 빠지고 나머지는 정상으로 뜨며, 무엇이 왜 빠졌는지 보인다. (Task 1)
2. **글자 입력값이 `-`로 시작하거나 줄바꿈을 담고 있다** → 스크립트 옵션으로 해석되지 않도록 거부한다. (Task 1)
3. **버튼을 연달아 누르거나 두 기기가 동시에 누른다** → 방문자 작업은 하나만 받고 나머지는 "지금 다른 인쇄 중"으로 거절한다. (Task 4, 5)
4. **스크립트가 끝나지 않는다** (파이에서 판 생성이 오래 걸림, maishift 응답 없음) → 제한 시간 뒤 그 작업만 실패로 끝내고 다음 작업을 받는다. (Task 4)
5. **프린터 USB가 빠져 있다** → 파이썬 오류 글자가 아니라 "프린터 연결을 확인해 주세요."를 보여준다. (Task 4)

**동작:**
- 각 스크립트 맨 위에 `SEED_PREFIX = "S"` 같은 상수를 둔다. 새 판을 만들 때 찍는 번호(영수증, 화면 출력, 저장 파일 이름의 태그)는 `SEED_PREFIX + 지금 번호`다.
- `--answer`(퍼즐)와 `--seed`(전리품, 타로)는 글자가 붙은 번호만 받는다. 대소문자는 가리지 않는다. 글자가 없거나 다르면 `ap.error`로 `"시드번호는 S로 시작합니다 (예: SM482913)"` 같은 문장을 낸다. 글자를 뗀 나머지는 지금 검사를 그대로 거친다.
- 전리품과 타로는 글자 뒤가 숫자 6자리가 아니면 같은 방식으로 거부한다.
- **난수는 바꾸지 않는다.** 판을 만드는 `random.Random(...)`에는 글자를 뗀 지금 값이 그대로 들어간다. `M482913`이던 스도쿠와 `SM482913`은 같은 판이다.
- 노노그램: `boards`의 키(`E03`)는 그대로 두고 보여줄 때만 `N`을 붙인다. `--list`도 `NE03`으로 보여준다.
- 문구: 스크립트의 설명글, 도움말, 오류 문장, 영수증의 "판 번호"를 모두 "시드번호"로 바꾼다. 영수증 머리의 번호 표기는 아홉 개 모두 `Seed No. {번호}`로 맞춘다 (노노그램, 전리품, 타로는 지금 `No.`다). README와 `docs/작업-정리.md`의 "판 번호"와 예시 번호도 바꾼다.

def test_prefixes_are_unique():
    letters = list(PUZZLES.values()) + list(DRAWS.values()); assert len(set(letters)) == len(letters)

@pytest.mark.slow
@pytest.mark.parametrize("script,letter", PUZZLES.items())
def test_puzzle_seed_round_trip(script, letter):
    code, out, err = run(script); assert code == 0, err
    seed = seed_of(out); assert seed.startswith(letter)
    code, out2, err = run(script, "--answer", seed.lower()); assert code == 0, err      # 소문자도 받는다
    assert seed_of(out2) == seed
    assert run(script, "--answer", seed[1:])[0] != 0                                    # 글자 없는 예전 번호는 거부
    assert run(script, "--answer", "Q" + seed[1:])[0] != 0

@pytest.mark.slow
@pytest.mark.parametrize("script,letter", DRAWS.items())
def test_draw_seed_round_trip(script, letter):
    code, out, err = run(script); assert code == 0, err
    seed = seed_of(out); assert re.fullmatch(letter + r"\d{6}", seed)
    code, out2, _ = run(script, "--seed", seed); assert code == 0 and out2.split("->")[0] == out.split("->")[0]   # 같은 결과

- Create: `hub.py`, `tests/test_hub.py`, `requirements-dev.txt`

**Interfaces:**
- Produces:

```python
ROOT: Path                      # hub.py가 있는 폴더
VISITOR, STAFF = "visitor", "staff"
MAX_SHEETS = {VISITOR: 4, STAFF: 20}

class HubError(ValueError): ...  # str(e)는 화면에 그대로 보여줄 한국어 문장

@dataclass(frozen=True)
class Field:  id: str; type: str; label: str; arg: str; audience: str; default: object
              choices: tuple[tuple[str, str], ...]; min: int | None; max: int | None
              pattern: str | None; max_length: int; example: str; required: bool
@dataclass(frozen=True)
class Mode:   id: str; label: str; audience: str; sheets: bool; args: tuple[str, ...]; fields: tuple[Field, ...]
@dataclass(frozen=True)
class Content: name: str; title: str; order: int; group: str | None; script: Path
               kiosk: bool; wait_between: float; modes: tuple[Mode, ...]
@dataclass(frozen=True)
class Group:  name: str; title: str; order: int
@dataclass(frozen=True)
class Catalog: contents: dict[str, Content]; groups: dict[str, Group]; errors: tuple[str, ...]
    def menu(self) -> list[Content | tuple[Group, list[Content]]]   # order 순, 묶음은 안의 콘텐츠와 함께

def load(root: Path = ROOT) -> Catalog
def load_nicknames(path: Path) -> list[str]          # 빈 줄과 '#' 줄은 건너뛴다
def build_args(content: Content, mode_id: str, values: dict, role: str, nicknames: Sequence[str] = ()) -> list[str]
def check_sheets(mode: Mode, sheets: int, role: str) -> int
def describe(catalog: Catalog, role: str, nicknames: Sequence[str] = (), kiosk_only: bool = True) -> dict
```

**설정 파일 규칙 (이 표가 스키마다):**

`content.toml` 최상위: `title`(필수), `order`(기본 100), `kiosk`(기본 true), `wait_between`(초, 기본 0), `script`(기본 `<폴더 이름>.py`), `[[mode]]` 목록.

`[[mode]]`: `id`(필수, 콘텐츠 안에서 유일), `label`(필수), `audience`(`"all"` 또는 `"staff"`, 기본 `"all"`), `sheets`(기본 true, false면 항상 1장), `args`(항상 붙는 인자, 기본 `[]`), `[[mode.field]]` 목록.

`[[mode.field]]`: `id`, `type`, `label`(필수), `arg`(`"--level"` 같은 옵션 이름, `""`이면 위치 인자), `audience`(기본 `"all"`), 그리고 종류별로:

| type | 추가 키 | 값 → 인자 |
|---|---|---|
| `choice` | `choices = [["표시", "값"], …]`, `default`(필수) | 값이 `""`이면 인자를 붙이지 않는다. 아니면 `arg 값` |
| `number` | `min`, `max`(필수), `default`(없으면 선택 항목) | 정수. 비어 있으면 붙이지 않는다 |
| `text` | `pattern`(전체 일치 정규식), `max_length`(기본 40), `example`, `required`(기본 true) | 앞뒤 공백을 뗀 문자열. 선택 항목이 비면 붙이지 않는다 |
| `names` | `min`, `max`(개수), `max_length`(이름 하나, 기본 8) | 문자열 목록을 `,`로 이어 `arg 이름,이름` |

묶음: `<묶음 폴더>/group.toml`에 `title`, `order`. 콘텐츠는 `<이름>/content.toml`(묶음 없음) 또는 `<묶음>/<이름>/content.toml`(그 폴더에 `group.toml`이 있을 때)에서 찾는다. 이름이 `.`으로 시작하는 폴더와 `.venv`는 보지 않는다.

**검사 규칙 (`build_args`, 모두 `HubError`):**
- 모르는 모드, `role`이 방문자인데 운영자 전용 모드 → 거부.
- `values`에 그 모드에 없는 키가 있거나, 방문자가 운영자 전용 항목에 값을 넣음 → 거부. 방문자에게 운영자 전용 항목은 "값 없음"으로 처리한다 (기본값도 붙이지 않는다).
- `choice`: 선택지에 없는 값 → 거부. `number`: 정수가 아니거나 범위 밖 → 거부.
- `text`: `max_length` 초과, `pattern` 불일치, `-`로 시작, 제어 문자(줄바꿈 포함) 포함 → 거부.
- `names`: 개수가 `min`~`max` 밖, 이름에 `,`나 제어 문자가 있거나 `-`로 시작, `max_length` 초과, 겹치는 이름 → 거부. `role`이 방문자면 모든 이름이 `nicknames` 안에 있어야 한다.
- 인자 순서: 위치 인자(`arg = ""`인 항목)가 맨 앞, 그다음 모드의 `args`, 그다음 나머지 항목을 설정 파일에 적힌 순서대로.

**`check_sheets`:** `mode.sheets`가 false면 요청 값과 상관없이 1을 돌려준다. 아니면 1~`MAX_SHEETS[role]` 밖일 때 `HubError`.

**`load`의 오류 처리:** 설정 파일 하나가 깨져 있으면(TOML 문법 오류, 필수 키 없음, 모르는 `type`, 스크립트 파일 없음, 이름 중복, 잘못된 정규식) 예외를 던지지 않고 그 콘텐츠를 빼고 `Catalog.errors`에 `"games/foo/content.toml: 이유"`를 넣는다.

**`describe`가 돌려주는 모양:**

```python
{"role": "visitor", "max_sheets": 4, "menu": [
    {"kind": "group", "name": "games", "title": "고전게임", "items": [<content>, …]},
    {"kind": "content", "name": "maimai", "title": "…", "modes": [
        {"id": "new", "label": "새 판", "sheets": True, "fields": [
            {"id": "level", "type": "choice", "label": "난이도", "default": "medium",
             "choices": [["쉬움", "easy"], …], "min": None, "max": None,
             "max_length": 40, "example": "", "required": True}]}]}]}
```

`role`에게 보이지 않는 모드와 항목은 뺀다. 보이는 모드가 없는 콘텐츠와 비어 있는 묶음도 뺀다. `kiosk_only`가 true면 `kiosk = false`인 콘텐츠를 뺀다. 방문자에게 `names` 항목은 `"type": "pick"`과 `"options": [닉네임…]`으로 바꿔 내보낸다. `pattern`은 내보내지 않는다.

```python
class Busy(Exception): ...                                   # 방문자 작업이 이미 있다
@dataclass
class Job: id: str; title: str; role: str; sheets: int; done: int; state: str; message: str
    def to_dict(self) -> dict                                # {"id","title","state","done","sheets","message"}
# state: "queued" | "running" | "done" | "failed" | "cancelled"

def run_script(script: Path, args: list[str], timeout: float) -> tuple[bool, str]   # (성공 여부, 사용자에게 보일 메시지)
def friendly(returncode: int | None, output: str) -> str                           # returncode None = 시간 초과

class JobQueue:
    def __init__(self, runner=run_script, preview: bool = False, timeout: float = 180, sleep=time.sleep)
    def submit(self, content: hub.Content, args: list[str], sheets: int, role: str) -> Job
    def get(self, job_id: str) -> Job | None
    def jobs(self) -> list[Job]                              # 대기·진행 중인 것과 최근 끝난 것(최대 50개), 오래된 순
    def cancel_all(self) -> int                              # 대기 작업은 취소, 진행 중 작업은 지금 장까지만 뽑고 취소
    def close(self) -> None
```

**동작:**
- 작업자 스레드 하나(데몬)가 대기열에서 하나씩 꺼내 `sheets`번 `runner(content.script, args + (["--preview"] if preview else []), timeout)`를 부른다. 한 장이 실패하면 남은 장을 뽑지 않고 `failed`가 되며 `message`에 실패 메시지가 들어간다.
- `content.wait_between`이 0보다 크면, 같은 콘텐츠의 직전 실행 시작으로부터 그만큼 지나도록 `sleep`한다. 작업이 달라도 적용된다 (maishift 요청 간격 5초).
- `submit`: `role`이 방문자이고 방문자 작업이 `queued`나 `running` 상태로 있으면 `Busy`. 운영자 작업은 항상 쌓인다.
- `run_script`: `subprocess.run([sys.executable, str(script), *args], capture_output=True, text=True, encoding="utf-8", errors="replace", env={**os.environ, "PYTHONUTF8": "1"}, timeout=timeout, cwd=hub.ROOT)`. 시간 초과는 프로세스를 죽이고 실패로 돌려준다.
- `friendly`: 시간 초과면 `"시간이 너무 오래 걸려 멈췄습니다. 다시 시도해 주세요."`. 출력에 `SerialException`, `could not open port`, `PermissionError` 중 하나가 있으면 `"프린터 연결을 확인해 주세요."`. 출력에 `Traceback`이 있으면 `"인쇄하지 못했습니다. 선생님께 알려 주세요."`. 그 밖에는 stderr의 마지막 비어 있지 않은 줄(스크립트가 `sys.exit("…")`로 낸 한국어 문장), 없으면 `"인쇄하지 못했습니다."`.

### Task 6: 키오스크 화면 (`kiosk/static/`)

**Files:**

이 작업은 프로젝트에 설치된 **`impeccable` 스킬**로 한다 (`.claude/skills/impeccable/`). 스킬의 Setup을 따르고, 이 화면의 모드는 **Operate**(방문자가 할 일을 끝내는 화면)다. 색, 글꼴, 분위기는 스킬의 절차에 따라 정해 사용자에게 보여주고 고른다. 갈무리 글꼴은 `/fonts/Galmuri11.ttf` 등으로 쓸 수 있다.

**화면이 반드시 해야 하는 것 (디자인과 상관없이):**

1. **콘텐츠 고르기**: `menu`의 묶음과 콘텐츠를 큰 버튼으로 보여준다. 묶음을 누르면 그 안의 콘텐츠가 보이고 뒤로 갈 수 있다.
2. **옵션 정하기**: 고른 콘텐츠의 모드와 항목을 `catalog` 데이터만으로 그린다. 콘텐츠 이름으로 갈라지는 코드를 쓰지 않는다. 모드가 여럿이면 첫 모드가 열려 있고 나머지는 고를 수 있다. 항목 종류별: `choice`는 버튼 묶음(기본값 선택됨), `number`는 − / 값 / + (범위 안에서만, 기본 없는 항목은 "자동"에서 시작), `text`는 입력칸(`maxlength`, `example`을 안내 글로), `pick`은 닉네임 버튼들(누르면 선택·해제, `min`~`max`개), `names`는 쉼표로 구분하는 입력칸. `mode.sheets`가 true면 장 수를 고른다 (방문자 1~4 버튼, 운영자 1~`max_sheets`).
3. **인쇄 중**: 뽑기를 누르면 `POST /api/print` 후 `GET /api/jobs/<id>`를 1초마다 묻는다. `queued`는 "순서를 기다리는 중", `running`은 "뽑는 중 2 / 3", `done`은 완료 표시 후 3초 뒤 첫 화면, `failed`는 `message`와 "처음으로" 버튼. 400과 409는 `error`를 보여주고 옵션 화면에 머문다.
4. **중복 방지**: 뽑기 버튼은 누른 즉시 비활성화되고 응답이 올 때까지 다시 눌리지 않는다.
5. **자동 복귀**: 인쇄 중이 아닐 때 60초 동안 터치가 없으면 첫 화면으로 돌아가고 입력값을 비운다.
6. **관리자**: `admin_enabled`가 true일 때, 첫 화면 제목을 2초 길게 누르면 숫자 키패드가 뜬다. 로그인하면 `catalog`를 다시 받아 그린다. 운영자일 때는 화면에 "관리자" 표시, 대기 작업 목록(`GET /api/admin/jobs`), "모두 취소"(`POST /api/admin/cancel`), "나가기"가 보인다. 운영자 화면은 3분 동안 터치가 없으면 로그아웃한다.
7. **아이패드**: 홈 화면에 추가했을 때 전체 화면으로 뜨도록 `apple-mobile-web-app-capable`, `viewport`(확대 금지), 홈 화면 아이콘을 넣는다. 가로·세로 모두에서 쓸 수 있고, 터치 대상은 최소 44pt, 글자 선택과 길게 눌렀을 때의 메뉴를 끈다. 구형 아이패드의 Safari에서도 돌도록 빌드 도구나 최신 문법 전용 기능에 기대지 않는다.
8. 서버에 닿지 않으면 "키오스크에 연결할 수 없습니다"를 보여주고 5초마다 다시 시도한다.
