# 화면 상자 키오스크 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 라즈베리파이 3B+ + 공식 7인치 터치스크린(800×480)에서 `?box=1`로 연 키오스크 페이지가 두 장 넘기기 화면과 화면 안 키보드(숫자·영문·두벌식 한글)로 동작하고, 설치 스크립트가 부팅 때 그 화면을 띄운다.

**Architecture:** 기존 `kiosk/static/app.js` 한 페이지에 상자 모드(`BOX` 상수, `<html class="box">`)를 더한다. 한글 조합은 순수 함수 파일 `hangul.js`, 화면 키보드는 `keyboard.js`로 떼어 `app.js`보다 먼저 싣는다. 파이에서는 `cage` + Chromium을 띄우는 새 systemd 서비스 `receipt-screen`을 `setup-pi.sh`가 선택적으로 설치한다.

**Tech Stack:** 바닐라 JS (ES2017까지), CSS, Flask(변경 없음), Node 내장 테스트(`node --test`, 개발 PC에 Node 24 있음), pytest, bash, systemd, cage, Chromium.

**Spec:** `docs/superpowers/specs/2026-11-21-box-kiosk-design.md`

## Global Constraints

- 브라우저 코드는 ES2017까지 (`?.`, `??` 금지). CSS는 `clamp()`, `:has()`, flex `gap`, `inset`, `aspect-ratio` 금지. 새 JS 파일도 아이패드에 내려가므로 같은 규칙.
- `?box=1`이 없으면 아이패드 화면은 지금과 픽셀 하나 다르지 않아야 한다. 상자 CSS는 전부 `.box` 아래에 둔다.
- 콘텐츠 이름으로 갈라지는 코드 금지. `content.toml`과 콘텐츠 스크립트는 고치지 않는다 (maimai 오류 문구 포함 — 지금 문구 "사이트에 연결하지 못했습니다 (...)"가 실패 화면에 그대로 뜨는 것으로 충분하다고 본다. 작성자 판단).
- 상자 화면에서 시스템 키보드·주소창·오류 창·마우스 커서가 보이면 실패.
- 상자 모드에서 '관리 페이지' 버튼은 숨긴다. `/admin`은 고치지 않는다.
- 화면 전환에 미끄러지는 움직임을 넣지 않는다. 기존 `tear` 움직임은 그대로.
- 누르는 것은 최소 높이 48px 안팎, 키는 약 70×54px, 본문 글자 16~18px.
- 화면 문구는 기존 말투(해요체, 짧게)를 따른다.

## Review Focus

1. **한글 조합의 모서리** — 겹받침 뒤 모음(닭+ㅏ → 달가), 겹모음이 안 되는 조합(ㅗ+ㅓ → 'ㅗㅓ'가 아니라 새 글자), 자모만 있는 상태에서 지우기. → Task 1 테스트에 고정.
2. **`max_length`에 걸린 채 조합** — 글자 수가 꽉 찼을 때 받침을 붙이는 것은 글자 수를 늘리지 않으므로 받아야 하고, 새 음절은 막아야 한다. → Task 2 `press` 테스트.
3. **입력 화면에서 60초 방치** — 키보드가 열린 채 첫 화면으로 돌아가고 키보드도 닫혀야 한다. 관리자 3분 로그아웃 때도 마찬가지. → Task 4 점검 항목.
4. **뽑는 중에 '뒤로'** — 인쇄가 진행 중일 때 뒤로를 누르면 처음 화면으로 가되 인쇄 추적(아래 띠·뜯긴 칸)은 이어져야 한다 (`goHome`의 `jobActive()` 처리 유지). → Task 3 점검 항목.
5. **서버가 늦게 뜨는 부팅** — Chromium이 서버보다 먼저 떠도 오류 페이지에 멈추지 않아야 한다. → Task 5 런처가 서버를 기다린다, Task 6 실기기 점검.

### Task 2: 화면 키보드 (`keyboard.js`)

**Files:**
- Create: `kiosk/static/keyboard.js`
- Create: `tests/js/keyboard.test.js`
- Modify: `kiosk/static/index.html` (`<div class="kbd" id="keyboard" hidden></div>`을 `#overlay` 앞에, `<script src="/static/hangul.js">`, `<script src="/static/keyboard.js">`를 `app.js` 앞에)
- Modify: `kiosk/static/style.css` (`.kbd` 아래 규칙. 키보드는 상자에서만 열리지만 선택자는 `.kbd`로 둔다)

**Interfaces:**
- Consumes: `Hangul.type`, `Hangul.erase` (Task 1).
- Produces (순수, 테스트됨):
  - `Keyboard.rows(kind, opts) -> Array<Array<string>>` — `kind`: `'number' | 'latin' | 'hangul'`. `opts`: `{ page: 'hangul'|'latin'|'symbols', shift: boolean, space: boolean }` (hangul 키보드만 `page`를 쓴다). 키 값 문자열 그대로, 특수 키는 `'BACK'`, `'SHIFT'`, `'DONE'`, `'PAGE:hangul'`, `'PAGE:latin'`, `'PAGE:symbols'`, 띄어쓰기는 `' '`.
  - `Keyboard.press(value, key, opts) -> string` — `opts`: `{ kind, maxLength }`. `'BACK'`은 hangul이면 `Hangul.erase`, 아니면 한 글자 지우기. 그 밖의 키는 hangul이면 `Hangul.type`, 아니면 붙이기. 결과 길이가 `maxLength`를 넘으면 `value`를 그대로 돌려준다.
- Produces (DOM): `Keyboard.open(opts)`, `Keyboard.close()`, `Keyboard.isOpen() -> boolean`. `open`의 `opts`: `{ kind, title, label, hint, value, maxLength, space, upper, onDone(value: string), onCancel() }`. `upper`는 latin 키보드가 대문자 고정(caps)으로 시작할지.

배치 (스펙 시안 그대로):
- `number`: `['1','2','3']`, `['4','5','6']`, `['7','8','9']`, `['BACK','0','DONE']`.
- `latin`: 숫자 줄 `1~0`, `qwertyuiop`, `asdfghjkl`, `SHIFT zxcvbnm BACK`, `_ . -` (`space`면 `' '` 추가) `DONE`. `shift`면 글자 키가 대문자. latin의 `SHIFT`는 켜고 끄는 고정키.
- `hangul` page `hangul`: `ㅂㅈㄷㄱㅅㅛㅕㅑㅐㅔ`, `ㅁㄴㅇㄹㅎㅗㅓㅏㅣ`, `SHIFT ㅋㅌㅊㅍㅠㅜㅡ BACK`, `PAGE:symbols PAGE:latin , ' ' DONE`. `shift`면 ㅂㅈㄷㄱㅅㅐㅔ → ㅃㅉㄸㄲㅆㅒㅖ. hangul의 `SHIFT`는 다음 한 글자만 (누른 뒤 자동으로 꺼짐).
- `hangul` page `latin`: latin과 같은 글자 줄 + 마지막 줄 `PAGE:symbols PAGE:hangul , ' ' DONE`.
- `hangul` page `symbols`: `1~0`, `- / : ( ) . , ? ! ~`, 마지막 줄 `PAGE:hangul PAGE:latin ' ' BACK DONE`.
