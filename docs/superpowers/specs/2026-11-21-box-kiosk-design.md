# 화면 상자 키오스크 설계

2026-11-21 작성. 대화에서 정한 내용과, 정하지 않아 작성자가 채운 내용을 구분해 적는다. "사용자 결정"은 바꾸면 안 되고, "작성자 판단"은 만들면서 더 나은 방법이 보이면 바꿔도 된다.

## 의도

지금 키오스크는 라즈베리파이가 서버와 프린터를 맡고, 방문자는 같은 와이파이에 붙은 아이패드에서 눌러 뽑는다 (`docs/superpowers/specs/2026-11-14-kiosk-design.md`). 여기에 **두 번째 설치 방식**을 더한다. 파이에 공식 7인치 터치스크린을 붙여 프린터·파이·화면이 한 상자가 되고, 전원만 꽂으면 그 화면에서 바로 골라 뽑는다. (사용자 결정)

아이패드 방식을 대체하는 게 아니라 나란히 고를 수 있는 선택지다. 상자는 와이파이가 없는 곳을 포함해 아무 데서나 켜서 쓸 수 있어야 한다. (사용자 결정)

## 목표

- 공식 7인치 터치스크린(800×480, 가로)에서 방문자가 고르고, 옵션을 정하고, 뽑을 수 있다.
- 글자 입력은 전부 화면 안 키보드로 한다. 관리자의 한글 입력도 상자 화면에서 끝난다. (사용자 결정)
- 파이를 켜면 사람이 손대지 않아도 상자 화면이 뜬다.
- 콘텐츠와 기능은 한 번만 만들면 아이패드와 상자 양쪽에 나온다.

## 하지 않는 것

- 아이패드 화면의 변경. `?box=1` 없이 열면 지금과 똑같아야 한다. (사용자 결정)
- 파이가 직접 와이파이(핫스팟)를 여는 기능. (사용자 결정 — 한글 키보드를 고르면서 빠졌다)
- 천지인 등 다른 한글 자판. 두벌식만. (사용자 결정)
- 카메라, 인쇄 상태판 등 7인치 화면의 다른 쓰임. 따로 이야기한다.
- 화면 크기를 보고 상자 모드를 자동으로 켜기. (사용자 결정 — 버린 방식 3)

## 이렇게 되면 실패다

- 상자용 기능을 넣으려고 콘텐츠의 `content.toml`이나 스크립트를 콘텐츠마다 고쳐야 한다.
- 아이패드에서 화면 키보드가 뜨거나, 배치가 바뀐다.
- 상자 화면에서 시스템 키보드·주소창·브라우저 오류 창·마우스 커서가 보인다.
- 다음 방문자가 앞사람이 쓰던 설정 화면이나 관리자 화면을 그대로 본다.
- 3B+에서 누를 때마다 눈에 띄게 늦다 (화면 바뀜이 0.5초를 넘는다).

## 제약

- **하드웨어**: 라즈베리파이 3B+ (RAM 1GB), 공식 7인치 터치스크린 (DSI, 800×480). (사용자 결정)
- **OS**: Raspberry Pi OS Lite 64비트, 아이패드 방식과 같다. 바탕화면은 깔지 않는다. (사용자 결정)
- **브라우저 코드**: `app.js`는 오래된 iPad를 위해 ES2017까지만 쓰고, `style.css`는 `clamp()`, `:has()`, flex `gap`, `inset`, `aspect-ratio`를 쓰지 않는다. 상자 모드 코드도 같은 파일에 들어가므로 같은 규칙을 지킨다. 새 파일(`keyboard.js` 등)도 아이패드에 함께 내려가므로 같은 규칙.
- **콘텐츠 이름으로 갈라지는 코드 없음**: `app.js` 머리말의 원칙. 키보드 종류도 항목의 성질(아래 표)로 정한다.
- **메모리**: 1GB에서 Chromium과 키오스크 서버, 인쇄 스크립트(Pillow)가 같이 돈다.

## 방식

고른 방식: **같은 페이지 안에서 상자 모드 켜기.** (사용자 결정) 상자는 `http://localhost:<KIOSK_PORT>/?box=1`을 연다. `app.js`가 이 표시를 보면 `<html>`에 `box` 클래스를 달고, 화면 흐름과 입력을 상자용으로 바꾼다. 고르기·입력 검사·인쇄 요청·대기열·관리자 처리는 기존 코드를 그대로 쓴다.

버린 방식:
- **상자 전용 페이지(`/box`)**: 아이패드 코드에 손대지 않지만, `app.js`의 입력 규칙·여러 장 뽑기·관리자 처리를 다시 짜야 하고 이후 기능을 두 번씩 만들어야 한다.
- **화면 크기로 자동 전환**: 설정이 없지만 작은 휴대폰이나 줄인 PC 창에서도 화면 키보드가 떠 시스템 키보드와 겹친다.

OS 쪽 고른 방식: **Lite + `cage` + Chromium.** (사용자 결정) `cage`는 앱 하나만 전체 화면으로 띄우는 Wayland 화면 관리자다. Pi OS Desktop은 메모리를 200MB쯤 더 쓰고 부팅이 느려 버렸다.

## 설계

### 화면 흐름 — 두 장 넘기기 (사용자 결정, 시안 A)

```
[처음 화면]                              [설정 화면]
┌ 도파민 박스 ───────── 뽑을 수 있어요 ┐   ┌ ← 뒤로  스도쿠 ────── 뽑을 수 있어요 ┐
│ [고전게임 13][오늘의 운세 4][리듬 1] │   │ 난이도 [쉬움][보통][어려움][지옥]│ 몇 장 │
│ ┌──────┬──────┬──────┐              │   │ 문제 번호 [________]            │[1][2] │
│ │1 스도쿠│2 부등호│3 노노 │  한 줄 3칸 │   │ 정답지 [문제만][정답도]         │[3][4] │
│ ├──────┼──────┼──────┤  길면 스크롤 │   │   (옵션 영역, 길면 스크롤)      │       │
│ │ ...   │       │      │              │   │                                 │[뽑기] │
└──────────────────────────────────────┘   └──────────────────────────────────────┘
```

- **처음 화면**: 머리띠(약 52px) + 묶음 탭 + 칸 격자. 칸은 한 줄에 3개. 오른쪽 패널은 없다.
- **설정 화면**: 칸을 누르면 화면 전체가 그 콘텐츠의 설정으로 바뀐다. 머리띠 왼쪽에 '← 뒤로', 가운데에 콘텐츠 이름. 본문 왼쪽은 모드·옵션 항목(길면 이 영역만 스크롤), 오른쪽 좁은 기둥(약 300px)은 장 수·같은 문제 여부와 뽑기 버튼(늘 보임). 모드가 여럿이면 모드 고르기는 옵션 영역 맨 위에 둔다. (작성자 판단 — 지금 패널의 내용 순서를 그대로 따른다)
- **뽑는 중·다 뽑음·실패**: 지금 패널이 보여 주는 진행/완료/실패 내용을 설정 화면 오른쪽 기둥(또는 설정 화면 전체)에 보여 준다. 다 뽑으면 `DONE_STAY`(3초) 뒤 처음 화면으로. (작성자 판단 — 지금 동작 그대로)
- **아래 띠(`.strip`)**: 지금처럼 다른 사람의 인쇄 진행을 알린다. 800×480에서 높이를 줄이거나 머리띠 상태 표시로 합친다. (빌더에게 맡김)
- 화면 전환에 미끄러지는 움직임은 넣지 않는다. 3B+에서 버벅인다. 칸이 뜯기는 짧은 움직임(`tear`)은 지금처럼 둔다. (작성자 판단)
- 크기 기준: 누르는 것은 최소 높이 48px 안팎, 글자는 본문 16~18px, 칸 제목 18px 이상. (작성자 판단)

### 화면 키보드 (사용자 결정, 시안 그대로)

글자 칸이나 숫자 칸을 누르면 설정 화면이 **입력 화면**으로 바뀐다. 위에 머리띠('← 취소' + "콘텐츠 · 항목 이름"), 그 아래 항목 이름·큰 입력 칸·도움말 한 줄, 화면 아래에 키보드가 깔린다. '완료'를 누르면 값을 넣고 설정 화면으로, '← 취소'는 값을 바꾸지 않고 돌아간다. 키는 약 70×54px.

| 키보드 | 모양 | 쓰는 곳 |
|---|---|---|
| 숫자 키패드 | 전화 키패드 순서 3×4, 화면 가운데. `⌫ 지우기`, `0`, `완료` | 관리자 PIN, 숫자 항목(`number`) |
| 영문 키보드 | 숫자 줄 + QWERTY 3줄 + `_ . -` + 완료. 시프트 있음 | `pattern`이 있는 글자 항목: 시드번호, maimai 아이디 |
| 한글 키보드 | 두벌식 3줄 + `⇧ 쌍`, `⌫`, `123`(숫자·기호), `A`(영문), `,`, 띄어쓰기, 완료 | `pattern`이 없는 글자 항목과 `names` 항목: 사다리 이름, 로또 상품 문구, 낱말 직접 넣기 등 (모두 관리자 전용 — 방문자에게는 서버가 `names`를 닉네임 고르기 `pick`으로 바꿔 내려주므로(`hub.py` `_describe_field`) 방문자는 한글 키보드를 볼 일이 없다) |

키보드 고르기 규칙 (작성자 판단 — 콘텐츠마다 설정하지 않으려고):
- `number` → 숫자 키패드. 지금의 빼기/더하기 버튼은 그대로 두고, 가운데 값을 누르면 키패드가 뜬다.
- `text`이고 `pattern`이 있음 → 영문 키보드. hub는 방문자용 글자 항목에 `pattern`을 강제하므로(`hub.py` 224행), 방문자가 보는 글자 항목은 전부 영문 키보드다.
- `text`이고 `pattern`이 없음, 또는 `names` → 한글 키보드.
- `choice`, `pick`은 키보드가 필요 없다.

**대화에서 말한 것과 달라진 점 (작성자 판단, 사용자 확인 필요)**: 대화에서는 "시드번호는 앞 글자(`SM`)를 고정하고 숫자만 누른다"고 했다. 실제 시드는 둘째 글자가 난이도(`E/M/H`)이고 콘텐츠마다 형식이 다르다 (`[Gg][EMHemh][1-3]\d{6}`, `[Ww][EMHemh][1-9A-Za-z]\d{6}` 등). 그래서 시드번호도 영문 키보드로 받는다. 영문 키보드는 시드 입력을 위해 대문자로 시작한다. (작성자 판단)

영문 키보드에서 아이디에 못 쓰는 글자(공백 등)는 키가 없다. 다만 `pattern`에 공백이 들어가는 항목(로또 수동 번호 `\d{1,2}( \d{1,2}){5}`, 관리자 전용)에서는 띄어쓰기 키를 보인다. (작성자 판단) 시드처럼 더 좁은 형식은 키를 막지 않고, 지금처럼 뽑기 전에 `pattern`으로 검사해 항목 아래에 오류를 띄운다.

한글 조합:
- 두벌식 오토마타를 `keyboard.js` 안에 순수 함수로 만든다: (지금 글자열, 누른 키) → 새 글자열. 겹받침(ㄳ ㄵ ㄶ ㄺ ㄻ ㄼ ㄽ ㄾ ㄿ ㅀ ㅄ), 겹모음(ㅘ ㅙ ㅚ ㅝ ㅞ ㅟ ㅢ), 받침이 다음 글자 초성으로 넘어가기(갑+ㅏ → 가바), `⌫`는 자모 단위로 지운다 (닭 → 달 → 다 → ㄷ).
- `⇧ 쌍`은 한 번 누르면 다음 한 글자만 쌍자음/ㅒ/ㅖ. (작성자 판단 — 휴대폰과 같게)
- `max_length`(names는 120)를 넘는 키는 받지 않는다.
- 이 조합 함수는 테스트를 붙인다. 방법은 빌더에게 맡긴다 (Node 내장 `node --test`, 또는 파이썬 테스트에서 JS를 실행하지 않는 다른 방법).

**관리자 PIN**: 지금 이름을 길게(2초) 누르면 뜨는 PIN 덮개(`openPin`)는 이미 화면 안 숫자 버튼으로 되어 있다. 상자 모드에서는 이것을 그대로 쓰되 800×480에 맞춰 크기만 조정한다.

상자 모드에서는 모든 `<input>`이 시스템 키보드를 부르지 않게 한다 (`readonly` 또는 `inputmode="none"`). 실제 상자에는 물리 키보드가 없지만, PC에서 `?box=1`로 열어 개발할 때 물리 키보드로 쳐도 깨지지 않으면 좋다. (빌더에게 맡김)

### 혼자 처음으로 돌아가기 (작성자 판단 — 지금 동작 그대로)

`app.js`에 이미 있다: 방문자는 60초(`IDLE_VISITOR`) 동안 안 누르면 처음 화면, 관리자는 3분(`IDLE_STAFF`) 동안 안 누르면 관리자에서 나간다. 상자 모드에서는 입력 화면도 "처음 화면이 아님"으로 쳐서 60초 뒤 돌아가게 한다. 입력 중이던 값은 버린다.

### 인터넷이 없을 때

maimai만 인터넷이 필요하다. 상자에서 미리 연결을 검사해 칸을 막지는 않고, 인쇄가 실패하면 실패 화면에 "인터넷에 연결되어 있지 않아 maimai 정보를 가져오지 못했어요" 같은 이유를 보여 준다. (작성자 판단 — 대화에서는 "칸에 미리 띄운다"고 했지만, 그러려면 콘텐츠 설정에 새 키를 넣어야 해서 실패 메시지로 낮췄다. 지금 maimai 스크립트가 연결 실패 때 어떤 오류를 내는지 빌더가 확인한다.)

### 설치 — `deploy/setup-pi.sh`

- 스크립트가 "화면 상자로 쓸까요? (y/N)"를 묻는다. 기본은 아니오이고, 아니오면 지금과 완전히 같다. (작성자 판단 — 질문 방식은 사용자 결정 "설치할 때 방식을 고른다"를 따른다) 다시 실행할 때 이미 상자로 설치돼 있으면 묻지 않고 유지한다. 비대화식 실행을 위해 `--box` 인자도 받는다. (빌더에게 맡김)
- 예라면 추가로:
  - `cage`, Chromium 설치 (Pi OS 버전에 따라 패키지 이름이 `chromium-browser` 또는 `chromium`).
  - 새 서비스 `receipt-screen` (`deploy/receipt-screen.service`): 부팅 때 tty1에서 `cage`로 Chromium을 키오스크 모드로 띄운다. `receipt-kiosk` 뒤에 뜨고, 죽으면 다시 뜬다 (`Restart=always`). 서버가 아직 안 떴을 때 오류 페이지가 남지 않게 한다 (서버를 기다렸다 열거나, 페이지가 스스로 다시 시도).
  - Chromium: 키오스크 모드, 오류·번역·복원 안내 창 끄기, 두 손가락 확대 끄기, 밀어서 뒤로 가기 끄기, 마우스 커서 숨기기.
  - 화면 꺼짐(블랭킹) 끄기.
- 설치가 끝나면 상자는 화면에 바로 뜨고, 아이패드나 휴대폰으로 `http://<호스트>.local`에 접속하는 것도 지금처럼 된다 (같은 서버).
- `kiosk/README.md`의 "라즈베리파이에 설치" 절에 상자 방식을 추가한다.

### 관리 페이지(`/admin`)

상자 모드에서는 대기열 덮개의 '관리 페이지' 버튼을 숨긴다. 관리 페이지(이용실적, 이미지, CSV)는 와이파이가 있을 때 휴대폰이나 PC에서 본다. 인쇄, 대기열 보기·취소, 관리자 들어가기/나가기는 상자에서 다 된다. (사용자 결정) 관리 페이지 자체는 고치지 않는다.

### OS 판과 실기기 점검

파이는 Raspberry Pi OS Lite 64비트다. Bookworm인지 Trixie인지는 정해 두지 않으므로 설치 스크립트가 둘 다 처리한다 (Chromium 패키지 이름 `chromium-browser`/`chromium` 중 있는 것). (사용자 답 + 작성자 판단) 사용자가 3B+와 7인치 화면을 갖고 있으므로, 계획 끝에 실기기 점검 단계를 넣는다: 부팅 후 화면 자동 표시, 터치, 세 키보드, 한글 조합, 인쇄, 60초 복귀, 화면 꺼짐 없음, 응답 속도.

### 화면 방향

공식 7인치는 기본이 가로다. 상자에 거꾸로 넣어야 하면 화면을 180도 돌리는 방법(KMS 회전)을 README에 적는다. 터치도 함께 돌아가야 한다. (빌더에게 맡김)
