# 영수증 프린터 키오스크 설계

2026-11-14 작성. 대화에서 정한 내용과, 정하지 않아 작성자가 채운 내용을 구분해 적는다. "사용자 결정"은 바꾸면 안 되고, "작성자 판단"은 만들면서 더 나은 방법이 보이면 바꿔도 된다.

## 의도

지금 프로그램은 PC 터미널 메뉴(`main.py`)로 콘텐츠 18가지를 골라 CPP-3000 영수증 프린터로 뽑는다. 이것을 나름청소년활동센터에 무인 키오스크로 두려고 한다. 라즈베리파이 3B+가 프린터에 연결되어 웹 페이지를 띄우고, 방문한 청소년이 아이패드에서 눌러 바로 뽑는다.

콘텐츠는 앞으로도 PC 터미널에서 계속 만든다. 새 콘텐츠를 만들었을 때 키오스크용 작업을 따로 하지 않아도 키오스크에 나타나는 것이 가장 중요한 요구다.

## 목표

- 아이패드 화면에서 콘텐츠를 고르고 옵션을 정해 인쇄한다. 미리보기는 없다.
- 방문자 화면과 관리자 화면을 나눈다.
- 콘텐츠 하나의 정의(제목, 옵션, 누가 쓸 수 있는지)를 한 곳에 적고, 터미널 메뉴와 키오스크 화면이 둘 다 그 정의로 만들어진다.
- 파이 전원을 켜면 사람이 손대지 않아도 키오스크가 뜬다.
- PC(Windows)에서도 프린터 없이 키오스크 화면을 띄워 개발할 수 있다.

## 하지 않는 것

- 키오스크에서 자유 텍스트 인쇄(`text`). 터미널에서만 쓴다. (사용자 결정)
- 화면 미리보기. (사용자 결정)
- 인터넷 공개. 센터 내부 네트워크에서만 쓴다.
- 용지 없음 감지. 1차에서는 넣지 않는다. (작성자 판단)
- 사운드 볼텍스 등 `docs/작업-정리.md`의 남은 일.

## 이렇게 되면 실패다

- 콘텐츠를 추가할 때 터미널용과 키오스크용을 따로 고쳐야 한다.
- 방문자가 아무 문구나 찍을 수 있거나, 한 번에 수십 장을 뽑을 수 있다.
- 기존 명령(`python main.py sudoku --level hard`, 각 스크립트 직접 실행)이 깨진다.
- 버튼을 여러 번 눌렀더니 같은 것이 여러 번 인쇄된다.

## 제약

- **하드웨어**: 라즈베리파이 3B+ (RAM 1GB), Raspberry Pi OS Lite 64비트, Python 3.13. 호스트 이름 `djwalnut`, 사용자 `wont0309`.
- **프린터**: 파이에서 `/dev/ttyACM0`으로 잡히는 것을 확인했다 (`1cbe:0002`). 포트는 환경 변수 `RECEIPT_PORT`로 넘긴다 (`receipt.py`의 기존 기능). 사용자가 `dialout` 그룹에 있어야 한다.
- **개발 PC**: Windows, Python 3.14. 두 환경 모두 표준 라이브러리 `tomllib`을 쓸 수 있다.
- **콘텐츠 스크립트 18개는 가능한 한 고치지 않는다.** 지금처럼 명령줄 인자를 받아 한 장을 만들고 끝나는 프로그램으로 둔다. 예외는 아래 "시드번호" 절의 변경뿐이다.
- **속도**: 부등호 스도쿠 어려움은 PC에서도 몇 초 걸린다. 파이에서는 더 느리므로 화면이 기다리는 상태를 보여줘야 한다.
- **maishift**: 요청 간격 5초를 지킨다 (지금 `main.py`의 `WAIT_BETWEEN`).

## 브랜치와 작업 흐름 (사용자 결정)

콘텐츠는 `receipt-contents` 브랜치에서 터미널로 만들고, `kiosk` 브랜치로 옮겨 키오스크에 올린다. 옮길 때 키오스크용 작업이 따로 없어야 한다.

- **`receipt-contents`**: 콘텐츠 스크립트, 설정 파일(`content.toml`), 허브(`hub.py`), 터미널 메뉴(`main.py`), 공용 모듈(`receipt.py`). 프린터와 터미널만 있으면 되는 것 전부.
- **`kiosk`**: `receipt-contents`에 키오스크 서버(`kiosk/`)와 파이 설치 파일(`deploy/`)을 더한 브랜치. 파이는 이 브랜치를 받는다.
- **옮기는 방법**: `git switch kiosk` → `git merge receipt-contents` → `git push`, 파이에서 업데이트 명령 한 번. 새 콘텐츠는 폴더와 설정 파일만으로 이루어지므로 병합만으로 키오스크 화면에 나타난다.
- **충돌이 나지 않게**: `kiosk` 브랜치는 `kiosk/`와 `deploy/` 폴더 안의 파일만 추가하고, `receipt-contents`에 있는 파일은 고치지 않는다. 키오스크 설명서는 `kiosk/README.md`, 키오스크 전용 패키지 목록은 `kiosk/requirements.txt`에 둔다.

## 시드번호 (사용자 결정)

- 영수증에 찍히는 번호의 이름은 "시드번호"로 통일한다 ("판 번호"라는 말은 쓰지 않는다).
- 시드번호의 첫 글자는 콘텐츠마다 다르다. 지금 번호 앞에 콘텐츠 글자 하나를 붙인다. 번호만 보고 어느 콘텐츠인지 알 수 있다.

| 콘텐츠 | 글자 | 예시 | 구성 |
|---|---|---|---|
| 스도쿠 | S | `SM482913` | 글자 + 난이도(E/M/H) + 숫자 6자리 |
| 부등호 스도쿠 | F | `FM482913` | 위와 같음 |
| 지뢰찾기 | M | `MM482913` | 위와 같음 |
| 미로찾기 | Z | `ZM482913` | 위와 같음 |
| 노노그램 | N | `NE03` | 글자 + 난이도(E/H) + 그림 번호 2자리 |
| 낱말 찾기 | W | `WM3482913` | 글자 + 난이도 + 주제 숫자 + 숫자 6자리 |
| 다른 그림 찾기 | D | `D5482913` | 글자 + 다른 곳 개수 + 숫자 6자리 |
| 전리품 뽑기 | L | `L482913` | 글자 + 숫자 6자리 |
| 오늘의 타로 | T | `T482913` | 글자 + 숫자 6자리 |

- 글자 배정(특히 미로찾기 Z, 다른 그림 찾기 D)은 작성자 판단이다.
- 이 변경 때문에 위 아홉 개 스크립트는 고친다. 글자를 붙이고 떼는 부분과 문구만 고치고, 판을 만드는 난수는 그대로 둔다. 그래서 예전 번호 `M482913`의 스도쿠는 새 번호 `SM482913`과 같은 판이다. 글자가 없는 예전 번호는 더 이상 받지 않는다. (작성자 판단)
- 전리품과 타로는 지금 `--seed`에 아무 글자나 받는다. 글자 + 숫자 형식만 받도록 스크립트에서 검사한다.
- 콘텐츠 설정 파일에 그 콘텐츠의 시드 글자를 적고, 허브가 글자가 겹치는 콘텐츠를 오류로 알린다. 새 콘텐츠를 만들 때 겹치는 글자를 쓰면 바로 드러난다.

## 검토한 방법

1. **중앙 목록**: `main.py`의 `CONTENTS`와 `ask_*`를 옵션 목록 파일 하나로 바꾼다. 한 파일에서 다 보이지만, 콘텐츠를 추가할 때 폴더 밖 파일을 고쳐야 한다.
2. **콘텐츠 폴더마다 설정 파일** (선택): 콘텐츠 폴더에 설정 파일을 두고 허브가 폴더를 훑어 찾는다. 폴더 하나가 곧 콘텐츠 하나라서 가장 모듈답다. 메뉴 순서와 묶음을 따로 정해야 하는 단점은 아래 "순서와 묶음"으로 푼다.
3. **터미널 화면을 웹으로 중계**: 코드 중복은 없지만 아이들이 누를 화면이 터미널 글자가 되고 방문자·관리자를 나눌 수 없어 제외했다.

사용자가 2번을 골랐다. "여기서 터미널로 만들면 손쉽게 키오스크에도 적용"이라는 요구에 가장 가깝기 때문이다.

## 설계

### 콘텐츠 설정 파일

콘텐츠 폴더마다 `content.toml`을 둔다. 폴더 이름이 콘텐츠 이름이고(`games/sudoku/` → `sudoku`), 스크립트는 기본으로 폴더 이름과 같은 `.py`다. 설정 파일이 있는 폴더만 콘텐츠로 인식한다.

설정 파일이 담는 것:

- 제목, 메뉴 안 순서
- 키오스크에 올릴지 여부 (`text`는 올리지 않는다)
- **모드** 목록: 터미널 메뉴에서 "1. 새 판  2. 정답 인쇄"처럼 번호로 고르던 갈래. 모드마다 이름, 항상 붙는 인자, 입력 항목들, 누가 쓸 수 있는지, 여러 장을 뽑을 수 있는지를 적는다.
- **입력 항목**: 종류(고르기, 숫자 범위, 짧은 글, 이름 목록), 표시 이름, 기본값, 스크립트 인자(`--level` 등 또는 위치 인자), 누가 쓸 수 있는지.
- 여러 장 뽑을 때 장 사이 대기 시간 (maimai는 5초)

모양은 대략 아래와 같다. 정확한 키 이름과 구조는 만드는 사람이 정한다.

```toml
title = "스도쿠"
order = 10

[[mode]]
label = "새 판"
[[mode.field]]
type = "choice"
arg = "--level"
label = "난이도"
choices = [["쉬움", "easy"], ["보통", "medium"], ["어려움", "hard"]]
default = "medium"

[[mode]]
label = "정답 인쇄"
sheets = false
[[mode.field]]
type = "text"
arg = "--answer"
label = "시드번호"
example = "M482913"
```

"누가 쓸 수 있는지"는 두 단계다. **모두**(방문자 포함)와 **운영자**(터미널과 관리자 화면)다. 터미널은 항상 운영자 수준이다.

### 순서와 묶음

묶음은 폴더 구조에서 나온다. `games/` 아래는 "고전게임", `fortune/` 아래는 "오늘의 운세", 맨 위 폴더(`maimai/`, `text/`)는 묶음 없이 바로 보인다. 묶음 폴더에는 묶음 제목과 순서를 적은 작은 설정 파일을 둔다. 묶음 안 순서는 각 콘텐츠의 `order` 값이다. 이렇게 하면 중앙 목록 파일이 필요 없다. (작성자 판단)

### 허브 (공용 부분)

설정 파일을 읽고, 입력값을 검사하고, 스크립트 인자 목록으로 바꾸는 부분을 터미널과 웹이 함께 쓰는 모듈로 만든다.

- 입력값 검사는 여기서 한다. 웹에서 온 값이 설정에 없는 선택지이거나 범위를 벗어나면 거부한다. 방문자 요청에 운영자 전용 모드나 항목이 들어 있어도 거부한다. 화면에서 숨기는 것만으로는 부족하다.
- 스크립트는 지금처럼 장마다 새 프로세스로 실행한다 (셸을 거치지 않고 인자 목록으로).

### 터미널 메뉴

`main.py`의 메뉴를 설정 파일에서 만들어지게 바꾼다. `ask_*` 함수 17개와 `CONTENTS`, `MENU`는 없어진다.

- `python main.py <이름> <옵션…>`으로 스크립트에 옵션을 그대로 넘기는 기능은 그대로 둔다.
- `p`(미리보기 모드 전환), 묶음 들어가기와 `b`(뒤로), 장 수 묻기(최대 20장)는 그대로 둔다.
- `text`는 예외다. 파일 고르기와 여러 줄 입력은 설정 파일로 표현하기 어려우므로 `ask_text`만 손으로 쓴 코드로 남긴다. (작성자 판단)
- 메뉴의 "연속 뽑기(Enter마다 한 장)" 갈래는 뺀다. 장 수 지정으로 대신할 수 있고, `python main.py loot --loop`로 직접 실행하는 것은 그대로 된다. (작성자 판단)

### 키오스크 서버

- Flask로 만들고 파이에서는 waitress로 띄운다. 기존 프로젝트와 같은 파이썬 가상환경을 쓴다. (작성자 판단)
- 화면은 빌드 과정 없는 HTML, CSS, 자바스크립트다. 서버가 설정 파일에서 읽은 콘텐츠 정의를 화면에 내려주고, 화면은 그것으로 버튼과 입력칸을 만든다. 콘텐츠를 추가해도 화면 코드는 고치지 않는다.
- **인쇄 대기열**: 인쇄 작업은 서버 안의 대기열에 들어가고 한 번에 하나만 실행된다. 화면은 작업 상태(기다리는 중, 뽑는 중 2/4, 끝, 실패)를 물어서 보여준다.
- **중복 방지**: 방문자 화면은 인쇄를 시작하면 끝날 때까지 다른 인쇄를 막는다.
- **실패 처리**: 스크립트가 오류로 끝나면 스크립트가 낸 메시지(예: "아이디 'x'을(를) 찾을 수 없습니다.")를 화면에 보여준다. 프린터 포트를 열지 못하면 "프린터 연결을 확인해 주세요"로 바꿔 보여준다. 여러 장 중 하나가 실패하면 남은 장은 뽑지 않는다.
- **개발 모드**: 환경 변수 하나로 모든 작업에 `--preview`를 붙여, 프린터 없는 PC에서 화면을 시험할 수 있게 한다.
- **이미지 정리**: 스크립트는 뽑을 때마다 `output/`에 이미지를 남긴다. 서버가 7일 지난 이미지를 지운다. (작성자 판단)

### 방문자 화면

흐름은 세 단계다.

```
┌─────────────────────────────┐   ┌─────────────────────────────┐   ┌─────────────────────────────┐
│  영수증 프린터               │   │  ← 스도쿠                    │   │                             │
│                             │   │                             │   │                             │
│  [고전게임 >] [오늘의 운세 >]│   │  난이도                      │   │        뽑는 중  2 / 3        │
│  [maimai]                   │   │  [쉬움] [●보통] [어려움]     │   │                             │
│                             │   │                             │   │                             │
│                             │   │  몇 장?  [1] [2] [●3] [4]    │   │                             │
│                             │   │                             │   │                             │
│                             │   │  [ 뽑기 ]      [정답 인쇄]   │   │                             │
└─────────────────────────────┘   └─────────────────────────────┘   └─────────────────────────────┘
   콘텐츠 고르기                     옵션 정하기                       인쇄 중 → 끝나면 처음으로
```

- 한 번에 **최대 4장**. (사용자 결정)
- 방문자에게 여는 범위: 고르기와 숫자 범위 항목은 전부 연다. 글자를 직접 입력하는 것은 **시드번호**(퍼즐 정답 인쇄, 전리품·타로 다시 뽑기)와 **maimai 아이디**뿐이다.
- **시드번호는 형식을 검사한다.** 전리품과 타로 스크립트는 `--seed`로 받은 글자를 검사 없이 "No. ○○○"로 그대로 찍는다 (퍼즐 스크립트들은 이미 검사한다). 그대로 두면 방문자가 아무 문구나 찍는 통로가 된다. 그래서 글자 입력 항목마다 설정 파일에 허용 형식을 적고 허브가 검사하며, 전리품과 타로 스크립트도 "시드번호" 절대로 형식을 검사한다.
- **전리품 레벨은 운영자 전용이다.** 전리품은 번호와 레벨을 함께 써서 아이템을 만든다(`roll`의 `f"{seed}/{level}"`). 방문자가 레벨을 고르면 영수증의 번호만으로는 같은 아이템을 다시 뽑을 수 없다. 방문자는 항상 무작위 레벨로 뽑고, 번호만으로 다시 뽑는다. (작성자 판단)
- **기기 수**: 아이패드 한 대를 기준으로 하지만, 같은 와이파이의 다른 기기가 주소를 알면 접속할 수 있다. 그래서 방문자 인쇄 잠금은 기기별이 아니라 서버 전체에 건다. 방문자 작업이 대기 중이거나 인쇄 중이면 다른 방문자 요청은 "지금 다른 인쇄 중"으로 거절한다. 관리자 요청은 대기열에 쌓인다. 요청 사이 대기 시간(쿨다운)은 두지 않는다. (작성자 판단)
- **사다리 타기**: 방문자는 이름을 입력하지 않고, 미리 준비한 닉네임 약 20개 중에서 2~8개를 눌러 고른다. 고른 수가 인원이 된다. (사용자 결정)
- **낱말 찾기**: 방문자는 난이도와 주제만 고른다. 낱말 직접 넣기는 운영자 전용이다. (사용자 결정)
- **maimai 아이디**: 스크립트의 기존 규칙(`maimai.py`의 `clean_handle`: 영문·숫자·`_`·`.`·`-`, 최대 40자)을 그대로 쓴다. 화면 입력칸도 40자로 제한한다. 프로필 주소 붙여넣기는 터미널에서만 받는다. (사용자는 "20자 정도, 말이 안 되는 선"이라고 했고, 이미 코드에 있는 40자 규칙이 그 선이라고 보았다. 작성자 판단)
- 일정 시간(약 1분) 아무도 누르지 않으면 첫 화면으로 돌아간다. (작성자 판단)
- 아이패드는 Safari에서 홈 화면에 추가해 전체 화면으로 띄우고, iOS "사용법 유도"로 잠근다. 이것은 설치 안내서에 적는다.

### 닉네임 목록

닉네임 약 20개를 텍스트 파일 하나에 한 줄씩 둔다. 센터에서 고치기 쉽게 코드와 분리한다. 초안은 만드는 사람이 써 두고 사용자가 고친다. 설정 파일에서 "이름 목록" 종류인 항목은 방문자 화면에서는 이 목록 고르기로, 터미널과 관리자 화면에서는 직접 입력으로 나타난다.

### 관리자 화면

- 방문자 화면에서 눈에 잘 띄지 않는 방법(예: 제목을 길게 누르기)으로 들어가고, 숫자 비밀번호를 넣는다. 비밀번호는 파이의 환경 설정에 두고 저장소에는 넣지 않는다.
- 방문자 화면과 같은 화면에 운영자 전용 모드와 항목이 더 보이고, 한 번에 **최대 20장**까지 뽑는다.
- 대기 중인 작업과 남은 장을 취소할 수 있다.
- 일정 시간 쓰지 않으면 방문자 화면으로 돌아간다.

### 파이 설치와 업데이트

- 저장소에 설치 스크립트를 둔다: 가상환경 만들기, 패키지 설치, `dialout` 그룹 추가, 서비스 등록.
- systemd 서비스로 부팅할 때 자동으로 뜨고, 죽으면 다시 뜬다. `RECEIPT_PORT=/dev/ttyACM0`과 관리자 비밀번호를 서비스 환경으로 넘긴다.
- 주소는 포트 번호 없이 `http://djwalnut.local`로 들어가게 한다. (작성자 판단)
- 업데이트는 명령 하나로 한다: 저장소에서 받아오고 서비스를 재시작한다. 콘텐츠를 PC에서 만들어 올리면 파이에서 이 명령만 실행하면 된다.
- 업데이트 명령은 브랜치 이름을 박아 두지 않고, 파이에 체크아웃되어 있는 브랜치를 그대로 받아온다. 저장소는 로그인 없이 받을 수 있다고 가정한다 (README의 clone 안내가 인증 없는 주소다). 비공개라면 설치 안내에 인증 설정 단계를 넣는다. (작성자 판단)
- 설치와 아이패드 설정 순서를 README에 적는다.

### 파이에서 달라지는 것

- `receipt.py`의 대체 글꼴 `C:/Windows/Fonts/msgothic.ttc`는 파이에 없다. 파일이 없으면 건너뛰게 되어 있어 오류는 나지 않지만, Galmuri11에 없는 글자(주로 maimai 곡 제목의 일부 한자)가 빈 네모로 찍힌다. 파이에서 쓸 대체 글꼴을 찾아 목록에 넣고 미리보기로 확인한다. 적당한 것이 없으면 그대로 두고 README에 한계를 적는다.

## 확인이 필요한 위험

- **센터 와이파이**: 공공기관 와이파이는 기기끼리 통신을 막아 두는 경우가 있다. 그러면 아이패드가 파이에 접속하지 못한다. 센터에서 먼저 시험해야 한다. 막혀 있으면 파이를 유선으로 연결하거나 별도 공유기를 두는 방법이 있다. 이 설계는 "아이패드와 파이가 같은 네트워크에서 서로 보인다"를 전제로 한다.
- **`.local` 이름**: 일부 네트워크에서는 `djwalnut.local`이 풀리지 않는다. 그때는 공유기에서 파이 IP를 고정하고 IP로 접속한다.

## 화면 디자인

화면 구조는 위 흐름을 따른다. 색, 글꼴, 분위기는 만드는 단계에서 프로젝트에 설치된 `impeccable` 스킬로 정한다. 저장소의 갈무리 글꼴은 웹 글꼴로도 쓸 수 있다 (라이선스 파일이 함께 있다). 아이패드 터치용이므로 버튼이 크고, 가로·세로 방향 모두에서 쓸 수 있어야 한다.

## 확인 방법

- 콘텐츠 17개(텍스트 제외) 각각에 대해, 설정 파일의 기본값으로 뽑은 결과가 지금 터미널 메뉴에서 Enter만 눌렀을 때와 같은 종류의 판이다 (같은 난이도, 같은 크기). 인자 목록이 글자 그대로 같을 필요는 없다. 예를 들어 지금은 빙고가 인자 없이 실행되지만 `--size 5`를 붙여도 된다.
- 모든 콘텐츠의 모든 모드가 `--preview`로 오류 없이 실행된다.
- 방문자 요청으로 운영자 전용 모드, 5장 이상, 설정에 없는 값을 보내면 서버가 거부한다.
- 새 콘텐츠 폴더와 설정 파일을 하나 추가하면 다른 파일을 고치지 않아도 터미널 메뉴와 키오스크 화면에 나타난다.
- 파이에서 재부팅 후 손대지 않고 아이패드로 인쇄가 된다.

## 만드는 사람에게 맡기는 것

- 설정 파일의 정확한 키 이름과 구조, 조건부 항목(예: 빙고에서 "빈 판"을 고르면 숫자 범위를 묻지 않음)의 표현 방법
- 서버와 화면 사이의 주고받는 형식
- 파일 배치 (서버 코드, 화면 파일, 설치 스크립트, 닉네임 파일의 위치)
- 관리자 진입 방법의 구체적인 동작과 자동으로 돌아가는 시간
- 프린터 장치 이름을 고정하는 방법 (USB를 다시 꽂아도 같은 경로가 되게 할지)
