# 새 콘텐츠를 kiosk 브랜치로 옮기는 방법

콘텐츠는 `receipt-contents` 브랜치에서 만들고, 다 되면 `kiosk` 브랜치로 머지한 뒤 파이에서 `bash deploy/update.sh`를 실행한다. 키오스크 화면은 `hub.py`가 콘텐츠 폴더의 `content.toml`을 읽어 저절로 만들기 때문에, 키오스크 쪽 코드는 고칠 필요가 없다.

```
receipt-contents  ──(만들기·커밋·테스트)──▶  kiosk로 머지  ──▶  push  ──▶  파이에서 update.sh
```

## 브랜치 규칙

| 브랜치 | 들어가는 것 | 고치는 곳 |
| --- | --- | --- |
| `receipt-contents` | 콘텐츠, `hub.py`, `main.py`, `receipt.py`, 테스트, 문서 | 키오스크 밖의 모든 파일 |
| `kiosk` | 위 내용 + 키오스크 웹 화면 | `kiosk/`, `deploy/`, `tests/kiosk/` 만 |

- 머지 방향은 항상 `receipt-contents` → `kiosk` 한 방향이다. 반대로 머지하지 않는다.
- `kiosk` 브랜치에서 콘텐츠 파일을 직접 고치면 다음 머지 때 충돌이 난다. 콘텐츠를 고칠 일이 생기면 `receipt-contents`로 돌아가서 고친다.

## 1. 머지 전 확인

`receipt-contents`에서 새 콘텐츠가 아래 모양을 갖췄는지 본다.

- [ ] 폴더 하나에 스크립트, 설정 파일이 함께 있다. 스크립트 이름은 폴더 이름과 같다.
      예: `rhythm/maimai/maimai.py`, `rhythm/maimai/content.toml`
- [ ] 묶음 안에 넣었다면 묶음 폴더에 `group.toml`(`title`, `order`)이 있다. 새 묶음이면 새로 만든다.
- [ ] 스크립트가 공용 모듈 `receipt.py`를 찾는 경로가 폴더 깊이와 맞다.
      묶음 안의 콘텐츠(`games/sudoku/`, `rhythm/maimai/`)는 `parent`를 세 번 쓴다.

      ```python
      sys.path.insert(0, str(Path(__file__).resolve().parent.parent.parent))  # 공용 모듈 receipt.py
      ```

- [ ] `output(sheet, "<묶음>/<콘텐츠>", ...)`의 폴더 이름이 실제 위치와 같다. 예: `"rhythm/maimai"`
- [ ] `content.toml`의 `seed_prefix`가 다른 콘텐츠와 겹치지 않는다.
- [ ] 아직 비어 있는 폴더(예: `rhythm/sdvx/`)를 남기려면 `.gitkeep`을 넣는다. git은 빈 폴더를 올리지 않는다. `content.toml`이 없는 폴더는 메뉴에 나오지 않는다.
- [ ] 콘텐츠 수나 메뉴 순서가 바뀌었으면 `tests/test_contents.py`와 `README.md`의 폴더 구조를 함께 고쳤다.

## 2. 커밋과 머지

맥 터미널에서 프로젝트 폴더로 가서 실행한다.

```bash
# 1) 콘텐츠 브랜치에서 커밋하고 올린다
git switch receipt-contents
git add -A
git commit -m "feat: <무엇을 추가했는지>"
git push

# 2) kiosk 브랜치로 옮겨 최신으로 맞춘다
git switch kiosk
git pull

# 3) 머지한다
git merge receipt-contents
```

- `git switch kiosk`가 "브랜치가 없다"고 하면, 이 컴퓨터에서 처음 쓰는 것이다. `git switch -c kiosk --track origin/kiosk`로 만든다.
- 충돌 없이 끝나면 머지 커밋이 저절로 생긴다. 3단계(테스트)로 넘어간다.

## 3. 충돌이 났을 때

`CONFLICT (content): Merge conflict in <파일>`이 나오면 그 파일을 열어 `<<<<<<<`부터 `>>>>>>>`까지를 고친다.

```
<<<<<<< HEAD                         ← kiosk 쪽 내용
    python maimai/maimai.py walnut
=======
    python rhythm/maimai/maimai.py gupying
>>>>>>> receipt-contents             ← 콘텐츠 브랜치 쪽 내용
```

고치는 기준:

- **경로, 폴더 구조, 기능**은 `receipt-contents` 쪽을 따른다. 새로 만든 쪽이 맞다.
- **kiosk 쪽에서만 바뀐 글**(예시 아이디, 문구 등)은 살린다. 위 예라면 `python rhythm/maimai/maimai.py walnut`로 합친다.
- 표시(`<<<<<<<`, `=======`, `>>>>>>>`)는 모두 지운다.

다 고쳤으면:

```bash
git add <고친 파일>
git commit --no-edit
```

머지를 처음부터 다시 하고 싶으면 `git merge --abort`로 머지 전 상태로 돌아간다.

kiosk 쪽에서 콘텐츠 파일이 바뀌어 있었다는 것은 규칙을 어긴 수정이 있었다는 뜻이다. 머지가 끝나면 그 수정을 `receipt-contents`에도 옮겨 두면 다음 머지 때 같은 충돌이 다시 나지 않는다.

## 4. 테스트

`kiosk` 브랜치에서 키오스크 테스트까지 함께 돌린다. 가상환경이 없으면 처음 한 번만 만든다.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt -r kiosk/requirements.txt
```

```bash
.venv/bin/python -m pytest -q
```

메뉴에 새 콘텐츠가 제대로 들어갔는지도 본다. 첫 줄에 `()`가 나오면 설정 파일 오류가 없다는 뜻이다.

```bash
.venv/bin/python -c "import hub; c = hub.load(); print(c.errors); print([m.name if hasattr(m, 'name') else (m[0].title, [x.name for x in m[1]]) for m in c.menu()])"
```

## 5. 올리기와 파이 반영

```bash
git push        # kiosk 브랜치를 올린다
```

파이에 SSH로 접속해 업데이트 스크립트를 실행한다.

```bash
ssh <사용자>@djwalnut.local     # 이름이 안 풀리면 IP로 (예: 192.168.0.48)
cd receipt-printer
bash deploy/update.sh
```

`update.sh`가 하는 일: `git pull --ff-only`로 새 내용 받기 → 패키지 설치 → `receipt-kiosk` 서비스 재시작 → 떴는지 확인. `업데이트 완료: <커밋>`이 나오면 끝이다. 아이패드에서 화면을 새로 고쳐 새 콘텐츠가 보이는지 확인한다.

## 자주 겪는 문제

| 증상 | 원인과 해결 |
| --- | --- |
| 테스트에서 `No module named 'flask'` | 키오스크 패키지가 없다. `.venv/bin/pip install -r kiosk/requirements.txt` |
| 스크립트 실행 시 `No module named 'receipt'` | 폴더를 옮긴 뒤 `sys.path`의 `parent` 개수가 안 맞는다. 1단계 확인 목록 참고 |
| 새 콘텐츠가 메뉴에 안 나온다 | `content.toml`이 없거나 오류로 빠졌다. 4단계의 `hub.load()` 출력에서 오류 문장을 본다. 묶음 안이면 `group.toml`이 있는지 본다 |
| 이미지가 예전 폴더에 저장된다 | `output(sheet, "...")`의 폴더 이름을 새 위치로 고친다 |
| 파이에서 `update.sh`가 `Not possible to fast-forward`로 멈춘다 | 파이에서 파일을 직접 고친 적이 있다. `git status`로 확인하고, 필요 없으면 `git restore .` 뒤에 다시 실행한다 |
| `서비스가 뜨지 않았습니다` | `journalctl -u receipt-kiosk -e`로 오류를 본다. 대부분 설정 파일 오타나 파이썬 오류다 |
| 머지했는데 `git push`가 거절된다 | 그사이 원격 `kiosk`가 바뀌었다. `git pull` 뒤에 다시 `git push` |
